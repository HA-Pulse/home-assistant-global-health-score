# HAGHS v2.5.0 Changelog

All changes on the `dev` branch after the v2.4.2 release.

## Unreleased

### psutil declared in the manifest (#238)

`manifest.json` lists `psutil>=5.9.0` as a requirement. HAGHS uses psutil for
disk usage; Home Assistant already installs psutil, so nothing is installed or
changed. Only a lower bound is given, never an exact version, so the psutil
version Home Assistant's own integrations use stays as it is. Files changed:
`custom_components/haghs/manifest.json`, `tests/test_manifest_requirements.py`,
`v2.5.0_CHANGELOG.md`.

### Recorder read through Home Assistant's helper (#236)

The config audit reads the recorder settings (keep days, entity filter)
through `homeassistant.helpers.recorder.get_instance()` instead of an internal
`hass.data` key. Without a recorder the audit behaves as before (no recorder
bonus) and logs one debug line. No change to scores or attributes. Files
changed: `custom_components/haghs/coordinator.py`,
`tests/test_recorder_get_instance.py`, `v2.5.0_CHANGELOG.md`.

### Repair confirmation never fails; type findings cleared

A HAGHS repair whose id this version does not know (for example one left by
another HAGHS version) can now always be confirmed and removed; before, opening
it failed. The "CPU and RAM are not measured" repair without stored entry data
now ends with "The HAGHS configuration entry no longer exists." instead of an
error. Type hints in the integration code are corrected so pyright (with the
project settings) reports no errors; six checks that do not fit Home Assistant's
types are ignored line by line with the rule name and a reason. No change to
scores, attributes or options. Files changed: `custom_components/haghs/repairs.py`,
`coordinator.py`, `config_flow.py`, `sensor.py`, `tests/test_repairs_fix_flow.py`,
`v2.5.0_CHANGELOG.md`.

### Developer tooling: pyright settings

`pyproject.toml` gets a `[tool.pyright]` section (Python 3.12 as Ruff's
target, `standard` checking, the local `.venv` for Home Assistant), so editors
and language servers that use pyright check `custom_components/` with the
project's settings (`tests/` is left out for now). No behavior change and no
new CI check; type hints are still checked in review. Files changed: `pyproject.toml`,
`v2.5.0_CHANGELOG.md`.

### An unreadable update-times store stays visible

Behavior change. If HAGHS cannot read the stored times when it first saw each
pending update (for example a file it has no permission to read, or a file
written by a newer HAGHS version after a downgrade), it no longer only writes
a debug line. It keeps a copy of the file next to it
(`.storage/haghs.update_first_seen.unreadable.<UTC time>`), logs one warning
with the traceback, and raises a HAGHS repair "HAGHS could not read its stored
update times" that names the copy; confirming the repair removes it. As
before, pending updates then count from that moment, so for up to 7 days they
do not lower the score. If no copy can be kept, the repair says so and HAGHS
does not save the file in that Home Assistant run, so it is never overwritten;
the warning then names why the copy failed, with the traceback of the copy
error and of the read error. The repair is HAGHS's own and does not count in the score. A file with broken
JSON is still handled by Home Assistant itself (it keeps a `.corrupt` copy and
raises its own repair). Files changed: `custom_components/haghs/const.py`,
`coordinator.py`, `repairs.py`, `strings.json`, `translations/en.json`,
`de.json`, `pt-BR.json`, `docs/faq.md`, `tests/test_update_grace_restart.py`,
`tests/test_update_first_seen_unreadable.py`, `v2.5.0_CHANGELOG.md`.

### Guidelines aligned with code and CI

`DEVELOPMENT_GUIDELINES.md` describes what code and CI do: type hints are
checked in review, not by CI; blocking file and system calls run through
`hass.async_add_executor_job` instead of async I/O libraries; the German and
Brazilian Portuguese translations must contain every key; a new
compatibility rule names the minimum Home Assistant version from `hacs.json`
and the Python target from `pyproject.toml`; error handling describes
`_safe_calc`, `pillar_fallback_count` and the kept last result (#103);
testing names the CI coverage limits (90 % for the integration, 80 % for
`coordinator.py`). `HAGHS_PHILOSOPHY.md` states that correctness beats
simplicity when in doubt. No behavior change. Files changed:
`DEVELOPMENT_GUIDELINES.md`, `HAGHS_PHILOSOPHY.md`, `v2.5.0_CHANGELOG.md`.

### PR template matches CONTRIBUTING and CI

The checklist names all three translation files, both Ruff commands, the
