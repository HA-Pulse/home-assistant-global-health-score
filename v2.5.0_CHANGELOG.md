# HAGHS v2.5.0 Changelog

All changes on the `dev` branch after the v2.4.2 release.

## Unreleased (documentation only)

### CONTRIBUTING and changelog aligned with the repo and CI

The documentation-only entries since v2.4.2 move from `v2.4.0_CHANGELOG.md`
to this file; new changelog files are named `vX.Y.Z_CHANGELOG.md`, and
CONTRIBUTING points to the newest one. CONTRIBUTING now states what CI and
tests check: `ruff check .` and `ruff format --check .`, 90 % coverage for
the integration and 80 % for `coordinator.py` (both commands under "Run
locally"), Python 3.14, the German and Brazilian Portuguese translation
rules, type hints checked in review, and SonarCloud as informational. No
behavior change. Files changed: `CONTRIBUTING.md`, `docs/changelog.md`,
`v2.4.0_CHANGELOG.md`, `v2.5.0_CHANGELOG.md`.

### Release badge color

The release badge at the top of the README uses the same color as the
website badge (`10B981` instead of `green`). No behavior change. Files
changed: `README.md`, `v2.4.0_CHANGELOG.md`.

### Roadmap: v2.5 issues

`ROADMAP.md` lists the v2.5 issues #217 (repair sync), #218 (Backup Health
from the built-in backup integration) and #219 (child devices) under
"Planned". No behavior change. Files changed: `ROADMAP.md`,
`v2.4.0_CHANGELOG.md`.

### Roadmap shows what is decided

`ROADMAP.md` lists under "Planned" what is committed for the next versions
(v2.5: #214; v3.0: #139, #140, #141) and links to the milestones, which show
the live state between releases. The repairs severity idea moves to "Not
scheduled yet". `CLAUDE.md`, `RELEASING.md` and `CONTRIBUTING.md` describe
how the roadmap is kept current and how documentation changes reach `main`.
No behavior change. Files changed: `ROADMAP.md`, `CLAUDE.md`,
`RELEASING.md`, `CONTRIBUTING.md`, `v2.4.0_CHANGELOG.md`.

### Unused issue-labeling command removed

`.claude/commands/label-issue.md` called a labeling script that was removed
together with the issue triage workflow, so the command no longer worked and
nothing referenced it. It is deleted. No behavior change. Files changed:
`.claude/commands/label-issue.md` (deleted), `v2.4.0_CHANGELOG.md`.

### FAQ: finding and removing empty devices

New FAQ entry "How do I find and remove empty devices?": a template that lists
`empty_devices` with links from `empty_device_ids`, the Pro card, deleting
through the device page (only where the integration supports it) or in the
integration, and the `haghs_ignore` label to keep a device. No behavior change.
Files changed: `docs/faq.md`, `v2.4.0_CHANGELOG.md`.

### Website link in the README

A "Website - hapulse.dev" badge follows the Buy Me a Coffee badge, and the
Abstract ends with "More at hapulse.dev", both linking to https://hapulse.dev.
No behavior change. Files changed: `README.md`, `v2.4.0_CHANGELOG.md`.

### Installs badge explained in the FAQ

Problem: the "Tracked Installs" badge showed only Home Assistant's opt-in
analytics without saying so. Fix: the badge reads "Installs (opt-in
analytics)" and links to the new FAQ entry "How many people use HAGHS?",
which names the source and Home Assistant's own estimate of how many
installations are not counted. Every FAQ question is now a heading, so each
answer has its own link; one question loses its em dash. No behavior change.
Files changed: `README.md`, `docs/faq.md`, `v2.4.0_CHANGELOG.md`.

### Backup source named

Problem: the docs did not say where the backup deduction comes from. Fix:
`docs/scoring.md` and the README scoring table name
`binary_sensor.backups_stale` of the Google Drive Backup add-on; without it
there is no backup check. No behavior change. Files changed: `README.md`,
`docs/scoring.md`, `v2.4.0_CHANGELOG.md`.

### Local Claude Code settings ignored

`.claude/settings.local.json` is added to `.gitignore`, so local tool
settings are never committed. No behavior change. Files changed:
`.gitignore`, `v2.4.0_CHANGELOG.md`.
