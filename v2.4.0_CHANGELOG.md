# HAGHS v2.4.0 Changelog

All changes on the `dev` branch after the v2.3.1 fix release.

## Features

### Recommendation texts are translatable (#114)

**Change:** The 17 recommendation templates (`REC_*` in `const.py`) are resolved at
runtime for the configured HA language via Home Assistant's translation system
(category `common` in `strings.json` / `translations/en.json`). English is the
fallback, then the `const.py` default, so a missing key can never produce an empty
recommendation.

**No behavior change:** for English users the rendered strings stay byte-identical
(guarded by a test that mirrors `translations/en.json` against `const.py`). No score
change.

**Deviation from the issue:** the issue proposed a custom translation category.
hassfest rejects custom top-level categories (`extra keys not allowed`), so the
templates live in the schema-valid `common` category.

**Files changed:**
- `custom_components/haghs/const.py` - `REC_TEMPLATES` mapping, comment updates
- `custom_components/haghs/coordinator.py` - `_async_load_rec_translations()`,
  `_rec()`, the recommendations builder, both result paths
- `custom_components/haghs/strings.json` and
  `custom_components/haghs/translations/en.json` - `common` category (1:1)
- `tests/test_recommendations_i18n.py` (new) - mirror test, fallback chain,
  override, error path, update cycle

### Repairs now affect the application score (#97)

**Change:** Open repair issues from HA's issue registry cost **5 points each**,
capped at **10 points**. While any repair is open, the application score is
**hard-capped at 99**, so the Config-Audit bonus can never mask a broken
integration. Counted are only issues that are active, not dismissed via HA's
native "Ignore" action and owned by another integration; repairs raised by
HAGHS itself are excluded (they describe the integration's own prerequisites).

**Score change:** this affects existing installations. An instance with open
repair issues scores lower than before, by design. The new attributes are
`repair_count` and `repairs` (`domain/issue_id` list), the new flag is
`rec_repairs`.

**Opt-out:** HA's native "Ignore" action on a repair (Settings > Repairs)
removes it from the count. No new HAGHS option is needed.

**Known overlap:** a broken backend often raises a repair issue *and* leaves
its config entry unhealthy, so one root cause can cost up to 25 points
together (15 for integration health, 10 for repairs). The caps keep that
double signal bounded.

**Files changed:**
- `custom_components/haghs/const.py` - `REPAIR_PENALTY_PER_ISSUE`,
  `REPAIR_PENALTY_CAP`, `REPAIR_LIST_CAP`, `REC_REPAIRS`, new flag key
- `custom_components/haghs/coordinator.py` - `_calc_repairs()`, the new
  `_ApplicationResult` fields, the new formula term, the extended hard cap,
  the recommendation branch and the flag
- `custom_components/haghs/sensor.py` - two new state attributes
- `tests/test_repairs_pillar.py` (new) - counting, caps, dismissal, own
  domain, score effect and the failure path
- `tests/test_score_explainability.py` - the invariant now covers repairs too
- `README.md` - pillar list, attribute table, flag table

## Bug Fixes

### Every missing score point is now explained (#92)

**Problem:** Two point sources were invisible: the Config-Audit bonus (+10 for
recorder purge days / entity filter) and the Integration Health penalty (5 pts
per unhealthy integration). A score well below 100 could therefore have no
explanation in the `recommendations` attribute at all, and no `rec_*` flag
pointed at the missing points.

**Fix:** Both sources now produce a recommendation line and a `rec_*` flag, and
two new attributes expose the raw numbers: `integration_unhealthy_count`
(number of config entries in SETUP_ERROR / SETUP_RETRY / FAILED_UNLOAD) and
`config_audit_bonus` (earned bonus points, 0-10). The new flags are
`rec_integration_health` and `rec_config_audit`, the latter meaning "bonus
points are missing", not "your configuration is bad". A new test
(`tests/test_score_explainability.py`) turns this into an invariant: no missing
point without a text and a flag.

**No score change:** the formula is untouched, every instance keeps the same
score values for a given state. Only the explanation grows.

**Files changed:**
- `custom_components/haghs/const.py` - `REC_INTEGRATION_HEALTH`,
  `REC_CONFIG_AUDIT`, `CONFIG_AUDIT_MAX_BONUS`, two new flag keys
- `custom_components/haghs/coordinator.py` - `_count_unhealthy_integrations()`,
  the new `_ApplicationResult` field, two recommendation branches, two flags,
  two result keys in both `_build_result` and `_neutral_result`
- `custom_components/haghs/sensor.py` - two new state attributes
- `tests/test_score_explainability.py` (new) - the invariant test
- `tests/test_recommendations.py`, `tests/test_recommendation_branches.py` -
  the all-clear cases now assume the fully earned bonus
- `README.md` - attribute table, flag table and pillar notes

## Tests

### Per-pillar coverage for the hardware and application pillars (#107)

**Problem:** `coordinator.py` was at 69 % and several scoring paths had no
test at all: the disk tiers, the classic CPU/RAM fallback with its clamps,
the integration-health cap, both database size paths, the recorder bonus, the
core-update lag and every `rec_*` flag branch. A future threshold edit could
then change scores without a single test failing.

**Change:** The suite grows from 103 to 211 tests and `coordinator.py`
reaches 100 % statement and branch coverage; the package total moves from
66 % to 87 %. No production code changed.

**Files changed:**
- `tests/factories.py` (new) - shared factories `make_coordinator`,
  `patch_psi` and `patch_disk` for the pillar tests
- `tests/test_hardware_tiers.py` (new) - tier boundaries of all five penalty
  helpers, PSI file parsing, `_get_float`
- `tests/test_hardware_disk.py` (new) - sd-card / emmc and SSD threshold
  cases
- `tests/test_hardware_assembly.py` (new) - PSI vs classic fallback, three vs
  four component average, sensor value clamps
- `tests/test_application_components.py` (new) - integration health, database
  sizes (external sensor and local sqlite), recorder bonus, core lag
- `tests/test_recommendation_branches.py` (new) - every recommendation text
  and `rec_*` flag branch
- `tests/test_ignore_paths.py` (new) - label, device and disabled-entity
  ignore paths plus the safety-net fallbacks
- `tests/README.md` - layout and coverage sections updated
